# MySQL → PostgreSQL 迁移实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 GFast V3.2 从 MySQL 完全迁移到 PostgreSQL 14+，删除 MySQL 驱动。

**Architecture:** GoFrame gdb 已抽象数据库层，业务代码不依赖 MySQL 专属语法。改动集中在 7 处：驱动 import、go.mod 依赖、数据库配置模板、代码生成配置、初始化 SQL（全量重写）、Web 初始化向导 API、README。

**Tech Stack:** GoFrame v2.10, `github.com/gogf/gf/contrib/drivers/pgsql/v2`, PostgreSQL 14+

**Spec:** `docs/superpowers/specs/2026-05-22-migrate-to-pgsql-design.md`

---

## File Structure

**修改的文件（7 个）：**
- `main.go` — 驱动 import
- `go.mod` / `go.sum` — 依赖
- `manifest/config/config.yaml.bak` — 运行配置模板
- `hack/config.yaml` — gfcli 代码生成配置
- `resource/data/gfast-v32.sql` — 初始化 SQL（全量重写为 PG）
- `api/v1/system/sys_init.go` — Web 初始化向导（去 charset required，Type 改 pgsql）
- `README.MD` — 文档

**不修改的文件：**
- `internal/app/common/service/casbin.go` — 纯 gdb 抽象
- `internal/app/system/dao/internal/*` — 生成的 DAO，类型映射通用
- `internal/app/system/model/**` — entity / do 模型，gdb 自动映射
- `manifest/docker/Dockerfile`、`manifest/deploy/kustomize/**` — 不含 DB 连接
- 业务 logic 中两处 `TRUNCATE` — PG/MySQL 共通语法
